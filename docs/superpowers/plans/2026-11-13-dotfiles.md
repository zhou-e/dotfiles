# Dotfiles + kb Repos Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A public dotfiles repo that rebuilds this machine's setup (Claude Code, status line, beads, shell, git, tmux), plus a private kb repo.

**Architecture:** Tracked files live under topic folders. `install.sh` symlinks most of them into `$HOME`, and copies the two files that apps rewrite. `capture.sh` copies those two back. `bootstrap/deps.sh` installs the tools the config depends on.

**Tech Stack:** bash, git, tmux 3.4, Node via nvm, ccstatusline, gh, bd (beads).

**Spec:** `docs/superpowers/specs/2026-11-13-dotfiles-design.md`

## Global Constraints
- The public repo must not contain the user's email, OAuth/credentials, AWS account IDs or SSO URLs.
- Every script runs under `set -euo pipefail`, honours `$HOME` (so tests can point it at a temp dir), and can be run repeatedly.
- No sudo in any script.
- Per the user's CLAUDE.md: no commits, remotes or pushes without the user's go-ahead. Commit steps below are staged only, and run when the user approves.

## Review Focus
1. `install.sh` run twice → no duplicate `source` line in `.bashrc`, no nested backups, links unchanged. (Task 2 test)
2. A real file already at a link target → moved to `<file>.bak.<YYYYMMDD-HHMMSS>`, not deleted. (Task 2 test)
3. An existing `~/.gitconfig.local` → never overwritten. On a fresh install, a template is created instead. (Task 2 test)
4. Node/nvm missing → `statusline.sh` prints a short fallback line and exits 0, rather than an error. (Task 1 test)
5. A secret or personal value is accidentally copied in → the repo secret-scan test fails. (Task 4 test)
